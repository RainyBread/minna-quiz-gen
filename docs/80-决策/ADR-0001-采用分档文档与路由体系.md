# ADR-0001：采用分档文档与路由体系

## 状态

已采纳（2026-11-17）。

## 背景

- 仓库原先只有根 `README.md`（200+ 行）和两个数据 README，混合了定位、流程、配比、数据分层、工具、CLI、测试。新会话需要全量阅读，上下文成本高。
- 文档与代码容易漂移：例如 `_mock_plan` 键名、`init --check` 的 72/52 口径、exporter legacy 回退。
- 没有本地文档检查；也没有 ADR/历史分离。
- 原方案假设 `src/intake|dict|gen|assemble|repair|types|bank|export|cli` 与插件注册表；实际是根入口 + 扁平 `core/`，且当前已有 Item 单一事实源、审计、迁移工具。

## 决策

1. 采用 L0–L3 分档：
   - L0：`CLAUDE.md` + `docs/00-总纲/`。
   - L1：`docs/10-契约/`。
   - L2：`docs/20-模块/`（与 `core/` 模块一一对应）。
   - L3：`docs/30-操作/`。
   - 记录：`docs/80-决策/`、`docs/90-归档/`。
2. `CLAUDE.md` 只放定位、12 条红线、4 条文档规则、任务路由、自动索引；≤120 行。
3. 只有 `CLAUDE.md` 常驻；00-总纲按需加载。路由预算：单任务 ≤3 篇 / ≤800 行（不计 CLAUDE.md 固定开销）。
4. 每条红线在唯一 L1 文档用 `<a id="redline-N">` 展开；lint 校验 1..12 各一次。
5. 文档 front-matter 用 `代码: 路径#符号` 绑定代码；lint 检查路径/符号存在，并覆盖 `core/*.py` 与根入口。
6. 引入 `tools/docs.py`：
   - `index` 生成 `docs/README.md` 与 CLAUDE 索引块；
   - `lint` 检查死链、锚点、红线唯一、路由预算、行数、中文比例、命令路径、DRIFT 引用、代码覆盖；
   - `--simulate-missing` 验证删除 L2 文档会产生死链。
7. 未决差异用 `DRIFT-NN` 登记在 L1-15，不在 L2 里写模糊的“可能有问题”。
8. 根 README 本轮不重写：它正被并发安全修复会话编辑；README 瘦身登记为 DRIFT-09，待安全改动落地后单独做。

## 后果

- 正面：新会话可按路由加载 2–3 篇；规则一处定义；文档漂移可被 lint/符号检查拦截；历史与决策分离。
- 代价：30+ 篇文档需要维护；每次改文档/长度要重跑 `index`；`lint` 有学习成本。
- 风险：并发重构期间代码接口会变；文档用符号锚点而非行号，最终 lint/测试前需复核。
- 不采用：单一大文档（上下文成本高）、只靠 README（无法分档）、引入 LLM 审文档（不可判定、成本高）。

## 备选方案

- 只建 `CLAUDE.md`，不建 docs：无法满足“细则按模块一处定义”。
- 把 docs 全放在 CLAUDE.md：违反 ≤120 行与按需加载。
- 引入完整 YAML/Markdown 框架：增加依赖；本项目只需受限 front-matter 与确定性 lint。
