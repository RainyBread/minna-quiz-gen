# ADR-0002：题型扩展用清单契约而非插件注册表

## 状态

已采纳（2026-11-17）。

## 背景

- 原文档方案要求“新增题型/词典/导出器走插件，core 零改动”。
- 实际代码没有插件注册表：题型由 `QuestionType` 枚举、`GENERATION_TYPES`、`TYPE_LABELS_ZH`、`quizgen` 分支、`prompts` 分支、`data/rules/question_types.json` 与测试共同决定。
- 当前只有 5 个可生成题型、4 个记录型题型；引入插件系统会显著增加抽象与测试成本，且没有第二个调用方。

## 决策

1. 不引入插件注册表。
2. 新增可生成题型必须同步修改七处：
   - `core/models.py#QuestionType`
   - `core/models.py#GENERATION_TYPES`
   - `core/models.py#TYPE_LABELS_ZH`
   - `core/quizgen.py` 的生成分支
   - `core/prompts.py` 的提示词分支（若用 LLM）
   - `data/rules/question_types.json`
   - 测试（意图/生成/挖掘按需）
3. 在 L1-16 维护这张清单；CLAUDE.md 红线 10 约束“禁止只改一处”。
4. 词典/导出器走适配器边界（`create_retriever`、`MDictIndex`、`core.exporter` 函数），但不承诺 core 零改动。
5. 如果未来出现明确的第三方扩展需求，再单独立 ADR 设计插件系统；本 ADR 不预设。

## 后果

- 正面：与现有代码一致；无新抽象；测试成本低；清单可 lint/评审。
- 代价：新增题型必须改 core 多处；无法热插拔；不能宣称“core 零改动”。
- 风险：清单漏项会导致意图/生成/导出某一环失效；用测试与 L1-16 检查表缓解。
- 相关：`RECORD_ONLY_TYPES` 只记录配比，不得因为“加了枚举”就宣称可生成。
