# 开发要诀

## 1. 构造优先，不靠论证

- 正确项先在本地钉死，再让 LLM 写包含它的载体句。
- 选项、答案、解析、来源配比在本地构造；LLM 不写选项、不写答案字母、不写解析。
- 唯一性与可接合性由 Item 的 slot 锚定、锁表语义场隔离、词性/活用形检查保证。
- 不增加“让模型解释为什么其他选项错”的评审式重试。

## 2. 运行时与构建期分开

- 运行时只读已提交的结构化 JSON：`vocab.json`、`grammar.json` 必读；其余可选。
- 导入、OCR、PDF 抽取、规则挖掘是构建期工具，默认启动与生成不执行。
- 注意：`main.py` 顶层仍导入 `core.miner`（DRIFT-07）；约束是“不执行”，不是“不导入”。新增功能不要把导入/OCR 拉进生成链。

## 3. 本地优先，逐级降级

- 事实源顺序：教材词表/语法点 → 锁表/原题库 → MDict/UniDic 增强 → LLM 载体句。
- 缺原题库：来源配比降级为纯新题，不中断。
- 缺 LLM：非模拟卷自动裁剪为读音/汉字题；模拟卷明确报错。
- 缺 UniDic：读音题使用教材已复核 `kana`；`unidic_verified=false` 的条目跳过读音/汉字题。
- 缺 MDict：拓展模式回退课内。
- 缺 `vocab.json`/`grammar.json`：硬失败 `ContextError`，不假装可运行。

## 4. 配比与曝光先于生成

- 来源槽位在扇出前确定；模型不参与配额分配。
- 已曝光考点不得再用原题；第二次出现必须走变体或新题。
- 单题失败记录并继续；LLM 连续 3 次非致命失败熔断，认证类错误立即熔断。

## 5. 安全默认

- API Key、`.env`、词典/教材/DB/日志/原题库/生成批次不进 Git。
- provider 与 base URL 必须匹配；非本地 `http://` 一律拒绝。
- LLM 请求日志只记 prompt，不记 headers、Key、response。
- 错误信息经 `sanitize_secret_text` 清洗后再显示。

## 6. 文档即提示词

- 改代码前先看对应 L1 契约；改契约先改文档再改码。
- 一条规则只在一处定义，别处只放锚点。
- 每个模块文档的“验收”必须是一条可执行命令；写不出验收的规则不要写。
- 文档结构与检查项见 [04-文档维护规范](04-文档维护规范.md)。
