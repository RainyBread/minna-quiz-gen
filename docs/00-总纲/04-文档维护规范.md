# 文档维护规范

## 1. 总纲

`CLAUDE.md` 是路由表，不是知识库。它只回答三件事：项目是什么、不能碰什么、去读哪篇。细则按模块分档写在 `docs/`，一条规则只在一处定义，别处只引用锚点。

文档即提示词：轻量、正向、可判定。写“做什么 + 怎么验收”；否定式只留给红线。每条规则尽量配一条本地命令；写不出验收的命令，删掉。

## 2. 分档

| 档次 | 位置 | 内容 | 变更门槛 | 加载 |
|---|---|---|---|---|
| L0 | `CLAUDE.md` + `docs/00-总纲/` | 定位、红线、开发要诀、术语、文档规范 | 显式批准 + ADR | 仅 CLAUDE.md 常驻；00-总纲按需 |
| L1 | `docs/10-契约/` | 跨模块接口、数据结构、传输格式、不变量 | 先改文档再改码；破坏性变更留 ADR | 按路由 |
| L2 | `docs/20-模块/` | 单模块实现细则、扩展点、已知缺口 | 随代码 PR | 按路由 |
| L3 | `docs/30-操作/` | 上手、数据制备、命令、验收、排障 | 命令实测输出为准，可脚本复核 | 按需 |
| 记录 | `docs/80-决策/`、`docs/90-归档/` | ADR、历史基线 | 只增不改 | 默认不加载 |

档次 = 约束力 + 加载优先级，不是重要性排名。L3 写得再详细也不构成约束。

## 3. CLAUDE.md 准入

只允许四类内容：

1. 项目定位（≤5 行）。
2. 项目红线（恰好 12 条，每条一行 + docs 链接）。
3. 文档规则（≤4 条）+ 任务路由表。
4. 目录级索引（`docs-index` 自动区块）。

硬上限 120 行。禁止：schema 全文、长代码示例、教程、变更日志、临时任务清单、从 docs 抄回的细则、易漂移数字（测试数/覆盖率/题量）。

`docs/README.md` 是篇级索引，由 `python tools/docs.py index` 生成；`CLAUDE.md` 的 `docs-index` 区块也由同一命令生成。两者都禁止手改。

## 4. front-matter

所有 docs 文件以受限 front-matter 开头（`docs/README.md` 除外）：

```yaml
---
模块: 装配审计与降级            # L2 必填
档次: L2                         # 全部必填：L0/L1/L2/L3/记录
说明: 一句话职责
代码: core/items.py#Item, core/runner.py#QuizRunner
契约: 10-契约/15-不变量与缺陷码.md   # L2 必填；相对 docs/
验收: python -m pytest -q tests/test_generator.py
校验: 2026-11-17
红线: 6, 9                       # 仅 L1；声明本篇唯一展开的红线
---
```

规则：

- 只支持 `key: scalar` 与 `key: a, b`；路径用 POSIX `/`，禁止绝对路径、`..`、反斜杠。
- `代码` 用 `路径#符号`；lint 检查路径存在且符号以 `class/def/NAME =` 出现。符号检查能抓重命名漂移。
- L1 必填：`档次/说明/代码/验收/校验/红线`。
- L2 必填：再加 `模块/契约`。
- L3 必填：`档次/说明/验收/校验`。
- L0 必填：`档次/说明/校验`；`验收` 可选。
- ADR：`档次: 记录` + `状态/日期/校验`。
- 每篇 ≤250 行；`CLAUDE.md` ≤120 行；单路由必读 ≤3 篇且合计 ≤800 行（不计 CLAUDE.md 固定开销）。

## 5. L2 同构模板

八小节顺序不得改动：

```markdown
## 1. 职责与边界
## 2. 输入输出契约
## 3. 数据与依赖
## 4. 本地不变量
## 5. 失败与降级
## 6. 扩展点
## 7. 验收
## 8. 已知缺陷
```

- §2 只引用 L1 锚点，不复制字段表。
- §4 每条不变量附可执行断言（测试/命令/代码函数）。
- §5 写缺陷码 → 失败链 → 补位；没有修复算子就明说。
- §6 写“加一个插件/题型/词典/导出器”的具体文件与注册行；没有插件机制就写清单。
- §7 写命令 + 实测输出（短）。
- §8 引用 `DRIFT-NN` 或写“无已知缺口（核实日期）”；quarantine 只在 L2-29（导入期）与 L2-26（迁移期）展开。

## 6. 维护要诀

1. **文档即提示词**：轻量、正向、可判定；否定式只留给红线。
2. **单一事实源**：一条规则一处定义；复制细则 = 制造漂移。
3. **按需加载，预算封顶**：单任务 ≤3 篇 / ≤800 行；路由表就是上下文预算表。
4. **模块边界 = 文档边界**：front-matter `代码` 绑定代码路径；lint 检查 `core/*.py` 与根入口均被覆盖。
5. **规则必须可判定**：每条规则配命令/断言；写不出验收的删掉。
6. **中文唯一 + 白名单**：标识符、命令、日语例词保留原文；术语以 `03-术语表` 为准。
7. **增量更新**：改小节不重写整篇；CLAUDE.md 只在红线或路由变化时动。
8. **契约先行**：L1 先改文档再改码；代码 PR 必带文档 diff。
9. **索引脚本生成**：docs/README 与 CLAUDE 索引块由 `tools/docs.py` 生成。
10. **本地 lint 代替评审**：死链、孤儿、重复红线、行数、front-matter、命令路径、DRIFT 引用全部脚本判定；不用 LLM 审文档。
11. **决策与历史分离**：ADR 追加不可变；变更日志、临时清单不进 CLAUDE.md 与 L1/L2。
12. **文档漂移即缺陷**：用 `DRIFT-NN` 登记，L1-15 是唯一登记表；修复后改状态，不删历史。

## 7. 本地 lint 与索引

```bash
python tools/docs.py index            # 生成 docs/README.md 与 CLAUDE.md 索引块
python tools/docs.py index --check    # 只检查新鲜度
python tools/docs.py lint             # 结构检查；失败 exit 1
python tools/docs.py lint --json      # 机器可读报告（路由行数/findings）
python tools/docs.py lint --simulate-missing "20-模块/24-装配审计与降级.md"
```

检查项：

- CLAUDE.md ≤120 行；四小节齐全；红线 12 条且每条一行。
- docs front-matter 必填字段、档次、日期；未知字段 fail。
- `代码` 路径/符号存在；`core/*.py` 与根入口被覆盖。
- Markdown 相对链接与显式 `<a id>` 锚点可解析；`契约` 可解析。
- 红线 1..12 各一个 owner；owner 有 `<a id="redline-N">`；CLAUDE 链接指向 owner。
- 路由必读 ≤3 篇、合计 ≤800 行。
- 每篇 ≤250 行；索引新鲜；中文比例 ≥0.30；`python` 命令脚本存在。
- `DRIFT-NN` 引用必须在 L1-15 登记；L2 §8 表态。

豁免：`docs/README.md` 只查新鲜度；`docs/90-归档/**` 只查链接；`docs/80-决策/**` 用 ADR 规则，默认不加载（文档维护路由可显式引用）。

不做的检查：外部 URL 可达性；标题自动 slug；文档命令的实际执行；密钥/词典名扫描（交给 `tools/check_repo_hygiene.py`）。

## 8. 变更流程

1. 改 L1 契约：先改文档，再改代码；在 `10-契约/` 留 diff。
2. 改 L2 实现：代码 PR 同批更新对应模块文档的 §4/§5/§7/§8 与 `校验` 日期。
3. 改红线/L0：显式批准 + ADR（`docs/80-决策/`）。
4. 新增题型：按 [16-题型扩展契约](../10-契约/16-题型扩展契约.md) 的清单一次改全。
5. 新增模块：在 `20-模块/` 新建文档，`代码` 字段覆盖新文件；lint 的 COVERAGE 会拦截漏文档。
6. 收尾：`python tools/docs.py index` → `lint` → `index --check` → `python -m pytest -q`。
