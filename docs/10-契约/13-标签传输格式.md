# 标签传输格式

<a id="redline-3"></a>
## 红线 3：本地事实优先，LLM 只写载体句

<a id="redline-5"></a>
## 红线 5：宽容标签，不要求严格 JSON

## 1. 当前协议

生成提示词要求模型只输出：

```text
[s]完整日语句子或短对话，把要考的词或形式用 [t]...[/t] 标出[/s]
```

- `[s]...[/s]`：载体句边界。
- `[t]...[/t]`：目标 span；本地取第一个 span。
- 不要求输出选项、答案字母、解析、中文翻译。
- 不要求 JSON；不要用 JSON 作为新协议。

## 2. 旧格式兼容

`parse_carrier_tags` 同时接受：

- `[SENTENCE]...[/SENTENCE]`，其中用 `[[ans]]...[[/ans]]` 标正确项。
- `[[blank]]` 作为空格占位符（不是标签）。
- `[[word]]` 简写：非 `blank/ans` 的短标记会当作 span。
- 全角括号 `［］`/`【】`、代码围栏、大小写差异。
- 缺少 `[/s]`/`[/t]`：用下一个顶层标签或文本末尾截断，并在 `warnings` 记录，不直接崩溃。

`parse_tags` 采用哨兵替换 `[[blank]]`/`[[ans]]`/`[[/ans]]`，避免把双括号当普通标签。

## 3. 意图标签

意图解析的 LLM 兜底使用：

```text
[MODE]practice 或 mock[/MODE]
[COUNT]题量[/COUNT]
[LESSONS]37-50 或 3 或 37,39[/LESSONS]
[TYPES]kanji_to_kana=5,grammar_fill=5[/TYPES]
[SCOPE]in_syllabus 或 mdict_distractors 或 extend[/SCOPE]
[TOPIC]主题[/TOPIC]
```

本地正则优先；只有缺少题型等关键信息时才调用 LLM 解析。

## 4. span 本地校验

`core.quizgen._validate_llm_span` 只做结构/事实核对：

- 空 span → `E_PARSE: [t] span is empty`。
- 与 `spec.correct_text` 完全一致 → 接受。
- 语法/表达：必须在 `approved_answer_forms` 中，否则 `E_ZERO`。
- 词汇：span 必须包含目标词形，或目标词形包含 span，否则 `E_ZERO`。
- 缺完整句 → `E_PARSE: 缺少完整句，拒绝裸框架题`。
- 缺决定性线索 → `E_MULTI: 题干缺少决定性线索，拒绝裸框架题`。

`E_MULTI` 是“缺线索”，不是“多解”。多个 `[t]` 当前只取第一个，不报错（DRIFT-04）。

## 5. 清洗与拒题

- `_stem_from_full_or_blank` 把 `[[ans]]` 内文本与固定正确项核对；不一致直接拒题。
- `_ensure_blank` 从括号/下划线/例句恢复 `[[blank]]`。
- `clean_option_text` 去空白/标点；`style_key` 判断礼貌体/普通体/て形/た形/助词。
- LLM 输出中的选项/解析即使出现，也不进入活跃路径；活跃路径只取 carrier/clue/translation。

## 6. 失败与降级

- 标签缺失/span 不合法：单题失败，记录 `RunFailure`，继续其它题。
- 连续 3 次非致命失败：熔断。
- 认证/连接类错误：立即熔断。
- 单题失败后按 original→variant→new→local-grammar 链补位。

## 8. 已知缺陷

- DRIFT-04：`E_MULTI` 语义是“缺线索”；多个 `[t]` 只取第一个，不显式拒绝。
- DRIFT-05：`build_question_prompt` 与 `TAG_TEMPLATE` 是未使用 legacy；新协议以 `build_carrier_prompt` 为准。
