# 数据分层与隐私

<a id="redline-11"></a>
## 红线 11：运行时最小闭包 = 代码 + vocab.json + grammar.json

<a id="redline-12"></a>
## 红线 12：不提交版权/隐私资产，日志只记 prompt

## 1. 运行时最小闭包

`core.context.load_context` 只硬性要求：

```text
data/textbook/big2_autumn/vocab.json
data/textbook/big2_autumn/grammar.json
```

其余均可选并自动降级：

| 缺失 | 行为 |
|---|---|
| `question_types.json` | 空默认；题型权重回退 `BLUEPRINT_2024`。 |
| `common_mistakes.json` | 空规则库；生成仍可运行。 |
| `course_profile.json` | 默认来源配比；模拟卷硬编码回退。 |
| `locks.json` | 无线索/锁词增强。 |
| `extension_vocab.json` | 无拓展池；拓展模式回退课内。 |
| `existing_question_index.json` | 无真题去重索引。 |
| `item_bank.local.json` | 纯新题；来源配比降级。 |
| SQLite | 运行时自动创建。 |
| UniDic/MDict/PDF/raw/drafts | 非运行时必需。 |

LLM Key 只影响 LLM 题；读音/汉字题离线可跑。模拟卷需要 LLM。

## 2. 提交边界

提交（allowlist）：

```text
data/textbook/big2_autumn/{vocab,grammar,exam_blueprint,course_profile,extension_vocab,locks}.json
data/textbook/big2_autumn/README.md
data/rules/{question_types,common_mistakes}.json
data/exams/existing_question_index.json
```

本地生成、不提交：

```text
data/exams/item_bank.local.json
data/exams/raw_*.json
data/exams/items/
data/exams/quarantine/
data/exams/big2_autumn/
data/db/ data/cache/ data/logs/
data/mdicts/ data/unidic-cwj-*/
data/textbook/*/drafts/ data/textbook/*/ocr/
教材pdf/ local_docs/ .env
```

`data/README.md` 只做目录指针；数据契约以本文为准。`tools/check_repo_hygiene.py` 会拒绝被跟踪的 PDF/docx/MDict/UniDic/SQLite/日志/原始题库/密钥文件。

## 3. 密钥与 provider

- `.env` 只填 `LLM_API_KEY`；`env.template` 是唯一可提交的模板。
- `LLM_PROVIDER=openai`（默认）或 `anthropic`。
- `LLM_API_KEY` 是显式跨 provider 覆盖。
- 未设置显式 Key 时，按 base URL host 选择：
  - `deepseek.com` → `DEEPSEEK_API_KEY`
  - `stepfun.com` → `STEPFUN_API_KEY`
  - `openai.com` → `OPENAI_API_KEY`
  - anthropic provider → `ANTHROPIC_API_KEY`
- 不匹配的 provider Key 不会被发送到错误 host。
- 非 localhost/私网的 `http://` base URL 会被拒绝，避免明文传 Key。
- `ensure_env_file` 创建 `.env` 时尝试 `0600`。

## 4. LLM 请求日志

`core.request_log` 只写 prompt 与元数据：

- 写：`timestamp`, `request_id`, `batch_id`, `item_id`, `model`, `attempt`, `prompt_hash`, `system`, `user`。
- 不写：headers、API Key、response 文本。
- 位置：`data/logs/llm_requests/*.jsonl`（gitignored）。
- 用于审计 prompt 是否泄漏正确项；`core.audit` 只读检查。

LLM 错误信息经 `core.llm.sanitize_secret_text` 清洗，再显示/记录。

## 5. 审计与隐私

- `python main.py --audit` 检查 request log 中的 key/干扰项/解析泄漏。
- 审计报告默认只给计数与掩码后的短文本，不打印完整答案或教材段落。
- `tools/check_repo_hygiene.py` 扫描 tracked 文件中的密钥模式与真实词典名；不因 `git` 失败而放行。

## 6. 验收

```bash
python init.py --check
python tools/check_repo_hygiene.py
python main.py --audit
```

预期：`init.py --check` 显示运行数据覆盖；hygiene 打印 `repo hygiene OK`；audit 的 `request_key_leaks` 为 0。
