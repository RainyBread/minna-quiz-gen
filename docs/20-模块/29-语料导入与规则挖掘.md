# 语料导入与规则挖掘

## 1. 职责与边界

构建期工具：把旧题库、2024 真题、教材词表/语法、扫描 PDF、规则语料转换成运行数据。默认启动与生成不执行；不作为运行时依赖。

- `core.importer`：旧词表/真题/教材/语法/blueprint 导入。
- `core.pdf_importer`：PDF OCR/视觉抽取，只产出 draft。
- `core.miner`：确定性挖掘 + LLM 增强 + 人工审核合并。
- `core.rule_defs`：稳定设误规则 ID。
- `tools/*`：命令行入口与复核。

## 2. 输入输出契约

输入：

- 旧项目语料：`dlut-nihongo-quiz/data/raw/...`（只读、gitignored）。
- 2024 真题 Markdown、教材 PDF、`local_docs/`。
- 现有 `vocab.json`/`grammar.json`/`exam_blueprint.json`。
- OCR/视觉 LLM（可选）。

输出：

- `data/exams/raw_*.json`（本地，gitignored）。
- `data/textbook/big2_autumn/vocab.json`/`grammar.json`/`exam_blueprint.json`。
- `data/textbook/big2_autumn/drafts/*.json`（本地）。
- `data/rules/question_types.json`、`common_mistakes.json`、`_mining_report.json`、`_draft/`、`history/`。

## 3. 数据与依赖

- Python 运行时依赖：`pydantic`、`python-dotenv`、`rich`、`openai`。
- 可选：`pymupdf`、`rapidocr_onnxruntime`、`Pillow`、`numpy`（OCR）；LLM Key（视觉/规则增强）。
- 源文件/PDF/docx/旧项目均 gitignored；仓库只提交结构化结果。
- `QualityStatus.QUARANTINED` 用于导入期质量不合格的题；不是 Item 级 quarantine。

## 4. 本地不变量

- OCR/视觉只写 draft；不直接覆盖已审核 `vocab.json`/`grammar.json`。
- 合并前必须人工审核；`review_*` 工具是唯一合并入口。
- 设误规则 ID 必须来自 `rule_defs.RULE_DEFINITIONS`；新增规则先定义再挖掘。
- 导入期 quarantine 题保留 `status=quarantined`，不进入原题库。
- 运行时 `context.load_context` 不导入本模块；`main.py` 顶层 import miner 是 DRIFT-07。

## 5. 失败与降级

- 源文件缺失 → 测试 skip；工具报缺失，不伪造数据。
- OCR 依赖缺失 → 跳过 OCR；可用已有 draft/数据。
- LLM 不可用 → `mine(offline=True)` 只跑确定性规则。
- 规则审核拒绝 → 不合并；保留 draft/history。
- 导入失败 → 记录 quarantine/错误；继续其它条目。

## 6. 扩展点

- 新语料来源：在 `core.importer` 增加 importer，输出同一 `RawQuestion`/`VocabEntry` 结构。
- 新 OCR 页映射：`DEFAULT_LESSON_PAGES` / `pdf_page_map.json`。
- 新设误规则：`rule_defs` + `miner` 分类 + `question_types.json` 的 `allowed_mistake_rules` + 测试。
- 新审核工具：`tools/review_*`，不直接改运行 JSON。
