# 入口与意图解析

## 1. 职责与边界

把自然语言请求解析成 `QuizPlan`，加载运行时上下文，分派到 CLI/REPL/自检/审计。不做生成、备料、选项构造。

- `main.py`：参数解析、REPL、单次生成、`--audit`/`--self-test`/`--list`/`--export`。
- `init.py`：环境检查、`.env` 引导、可选 `--remine`，然后进入 REPL。
- `quiz.py`：薄入口，`python quiz.py audit [BATCH_ID]`；其余参数转交 `main.main`。
- `core.intent`：本地正则优先，标签式 LLM 兜底。
- `core.context`：只读紧凑 JSON；不导入语料、不跑 OCR、不重新挖掘。

## 2. 输入输出契约

输入：自然语言 `request`、CLI 开关（`--mock`/`--scope`/`--topic`/`--use-case`/`--offline` 等）、`AppContext`。

输出：`QuizPlan`（字段见 [L1-14](../10-契约/14-任务单与配比.md)）。

关键行为：

- 课次：1-14 视为课程课次，加 36 得教材课次；37-50 直接使用。
- 题量：阿拉伯数字/中文数字 + “道/题/个”；默认见 `intent.DEFAULT_COUNT`。
- 题型：别名映射 `TYPE_ALIASES`；阅读/排序/完形在意图层拒绝。
- 模拟卷：`mode=mock`，80 题五类，强制课内。
- 缺关键信息时 CLI 追问，而不是直接抛错。

## 3. 数据与依赖

- `settings.vocab_path`、`settings.grammar_path`：必读。
- `question_types.json`、`common_mistakes.json`、`course_profile.json`、`existing_question_index.json`：可选。
- LLM 只用于意图兜底；需要 `LLMClient` 可用。
- 无 UniDic/MDict/原题库也能解析。

## 4. 本地不变量

- `QuizPlan.total == sum(type_plan.values())`。
- 课次映射满足 `course = textbook - 36`。
- 模拟卷 `count=80` 且 `grammar_fill=25`（数据/硬编码回退一致时）。
- 不支持的记录型题型不得进入 `type_plan`。
- `load_context` 只读 JSON；缺失必读文件抛 `ContextError`。

## 5. 失败与降级

- 空输入/无法识别 → `IntentError`；CLI 显示用法。
- 不支持的题型 → `UnsupportedTypeError`。
- LLM 意图解析失败 → 回退本地默认/追问。
- `vocab.json`/`grammar.json` 缺失 → `ContextError`，硬失败。
- `init.py --check` 只检查，不写数据。

## 6. 扩展点

- 新题型别名：`core/intent.py` 的 `TYPE_ALIASES`；同时按 [L1-16](../10-契约/16-题型扩展契约.md) 改全套。
- 新用途/配比：`course_profile.json` 的 `source_mix_presets` 与 `USE_CASE_KEYWORDS`。
- 新 REPL 命令：`main.run_repl` 的分支；不要绕过 `QuizPlan`。
